## Known Limitations

### Open Findings (non-blocking)

**BV-3 (nit): focus after a forced dialog reopen** (`browser-verification.md`, round 2)
- **Where:** below 1024 px (sheet or drawer). It occurs when Chrome force-closes the create dialog on a repeated Escape after the user declined to discard.
- **What happens:** the dialog reopens with the input and route intact, but focus lands on the panel **heading** instead of the field the user was editing.
- **Cause:** in `Panel.tsx`, `showModal()` moves focus before `lastFocused.current` is read, and the `onFocus` tracker overwrites the remembered field.
- **Impact:** the user must navigate back to the field. Nothing is lost or unreachable.
- **Testing gap:** the jsdom stub's `showModal` does not move focus, so the unit test does not catch this.
- **Follow-up:** coder or debugger.

**N5 (nit): test hygiene in `Panel.test.tsx`** (`review.md`, round 5)
- **What happens:** the teardown deletes jsdom's native `HTMLDialogElement.prototype.open` accessor instead of restoring it.
- **Impact:** nothing fails today, because the file has a single test and Vitest isolates files. A second test added to this file would break.
- **Follow-up:** test-generator or coder.
